01 · Purpose

Why use Intelligent Agents?

Important: Intelligent Agents and Early Alerts are separate systems

D2L Intelligent Agents identify students based on course criteria. They do not automatically create, submit, or update a formal Lone Star College Early Alert. If a referral is needed, faculty must use the institution's Early Alert for Faculty process separately.

02 · If sending emails

Configure the From & Reply-To fields

If you plan to send emails, update the instructor identity and Reply-To address in each course.

1

Open Course Management → Course Admin → Intelligent Agents.

2

On the Agent List, click Settings in the upper-right corner.

3

Choose Set custom values for this course.

4

Enter the custom sender display name and a working Reply-To address, then Save.

Repeat after every course copy

User-specific values do not transfer with copied Intelligent Agents. Without a valid Reply-To address, students may receive a bounce-back error when replying.

Sender address distinction

Brightspace controls the underlying sender address. Faculty personalize the name and set an inbox for replies.

03 · Create an agent

Start with the Agent List

Create an agent and choose its initial enabled state. Existing agents can also be enabled or disabled directly on the Agent List.

Course Management→Course Admin→Intelligent Agents→New Agent
1

Select Course Admin, then Intelligent Agents under Communication.

2

Click New Agent from the Agent List.

3

Enter a descriptive Agent Name, such as “7-Day No Course Access.”

4

Check Agent is enabled to make the agent available for runs.

Why descriptive names?

A descriptive title clarifies the purpose when faculty review several agents or copy a course.

04 · Agent list controls

Make an agent active from the Agent List

Faculty do not need to reopen the editor to enable or disable an existing Intelligent Agent.

1

Open Course Management → Course Admin → Intelligent Agents.

2

On the Agent List, check the box beside the agent you want to activate.

3

Select Enable in the toolbar above the list. The agent becomes enabled.

4

To pause an agent later, select its checkbox and choose Disable.

Enable does not mean Run Now

Enabling does not start a run. Scheduled agents run at the chosen time. With No Schedule, use Run Now.

Also available when creating an agent

In the New Agent form, select Agent is enabled. The Agent List provides a second way to manage this status after saving.

Check the status

Review the status indicator next to each agent name after enabling or disabling. In the sample list, a circle with an X marks a disabled agent.

05 · Scheduling

Choose when an agent runs

Scheduling controls when Brightspace evaluates student activity. Select a frequency appropriate to your outreach purpose.

Manual

No Schedule

Faculty choose Run Now from the Agent List to start an evaluation.

Automatic

Daily or Weekly

Set repeat frequency, day of week where appropriate, and scheduled time.

Configure a recurring schedule

1

Under Scheduling, open Frequency.

2

Select Daily or Weekly and define the interval.

3

Set the scheduled time, and optional start and end dates.

Scheduling is different from repetition

A daily run checks the criteria daily. The Actions section determines whether eligible students receive another message on later runs.

06 · Selecting learners

Define your criteria

Specify who is evaluated and whether activity means D2L login or access to your individual course.

Role in Classlist

Select Users with specific roles and check Student to restrict evaluation to enrolled learners.

Take Action on Activity

Login Activity tracks access to D2L broadly. Course Activity tracks actual entry into your course.

Example faculty decision

Choose Course Activity when you want an alert about a student who logs into Brightspace but has not opened your course for seven days.

Release conditions evaluate specific behaviors in the Quizzes, Assignments, and Content tools.

Quiz

Low score

Score below 50% on a selected quiz.

Assignment

Missing submission

No submission to a selected folder.

Content

Steps for release conditions

1

Locate Release Conditions under Criteria.

2

Click Create for a new condition or Browse to attach an existing one.

3

Copied courses

08 · Messages and frequency

Configure actions and email

Set how often an agent takes action. Email is optional. You can run an agent, identify students, and inspect its results without sending student messages.

First time criteria are met

Send one notification when a student first qualifies. Useful for a failed quiz alert.

One-time action

Every time criteria are met

Send another notification every eligible run. Useful for repeated inactivity checks, with attention to email frequency.

Repeat action
Email is optional, not required

Leave unchecked: the agent evaluates students and records run results without sending an email. Check “Send an email when the criteria are satisfied”: the agent sends a message to eligible users when an action occurs.

Only if you choose email

Enter appropriate recipients and put {InitiatingUser} in Bcc for student privacy. The following slide explains the fields.

09 · Protect student privacy

Address email using To and Bcc

If you choose to send email, use the To and Bcc fields to protect student address visibility. Skip this configuration when email remains unchecked.

Use the recommended recipient fields

ToEnter an instructor's or advisor's institutional email if a copy is needed.
CcLeave blank unless an additional recipient is appropriate.
Bcc{InitiatingUser} inserts the eligible student as a blind-copy recipient.
SubjectUse a clear course-relevant title.
Privacy rationale

The Bcc field keeps a student's email address out of the visible recipients list. Review any copies sent to advisors under your institution's student privacy rules.

Check before saving

Verify the instructor Reply-To address, the Bcc token, the subject, and the complete message. Click Save and Close when finished.

10 · Email personalization

Use replace strings

If the email action is enabled, Brightspace replaces these strings with course and learner information when it sends the message.

Replace stringInformation inserted
{InitiatingUserFirstName}
{InitiatingUserLastName}		Student first and last name
{LastCourseAccessDate}Date of last course access
{LoginPath}System login address
{OrgUnitName}Specific course section name
Sample message

Hello {InitiatingUserFirstName}, your last access to {OrgUnitName} was {LastCourseAccessDate}. Please sign in using {LoginPath} and review this week's activities.

Personalization checklist

  • Greet each student by name.
  • Identify the correct course.
  • Include relevant activity information.
  • Provide a clear next action.

Important distinction

Daily scheduling does not mean daily emails when the repetition choice is “first time only.” Configure both options intentionally.

12 · Test and deploy

Understand Practice Run vs. Run Now

Practice Run tests your criteria without student emails. Run Now evaluates immediately, with email delivery only when its checkbox is selected.

Practice Run

0 student messages sent

Simulates the evaluation and identifies students who meet the criteria.

  1. Open agent dropdown.
  2. Choose Practice Run.
  3. Click Run and Done.
  4. Review the # users identified link after completion.

Run Now

Email only when enabled

Immediately evaluates criteria and saves run results. Sends messages only when the optional email action is checked and a student qualifies.

  1. Open agent dropdown.
  2. Choose Run Now.
  3. Click Run and Done.
  4. Review results or run history.
Before Run Now

Verify roles, criteria, timing, and repetition settings. If using email, also review recipients, message content, and the Reply-To address. A manual run does not automatically create an Early Alert.

13 · Review run results

Find the results on the Agent List

After any run, use the Agent List to find identified students and review prior run history.

Step 1

Find the agent row

In the Agent List, locate the agent you ran. Check the Last Run Date column.

Step 2

Click the results link

Under Results of Last Run, select the “# users identified” link to inspect the students and actions for the latest run.

Step 3

View older runs

Select the agent's down arrow → View History. Open a prior run to review its identified users and recorded actions.

Read the results in context

The users identified count shows students meeting the criteria. A run result does not automatically mean an email was sent, and no Early Alert is created. Examine Action Taken when reviewing a particular run.

14 · Maintain and support

Ready for the next semester?

Before reusing an agent, review its dates, criteria, enabled status, and any optional email settings.

Use Manage Dates when eligible

Recurring agents with a start date or end date can be edited or bulk-offset with the Manage Dates tool.

Which agents are excluded?

One-time schedules and recurring agents without start or end dates do not appear in Manage Dates. Edit those directly inside Intelligent Agents.

Course rollover checklist

  1. If emailing, update the custom From name and Reply-To address.
  2. Confirm Student role and attached release conditions.
  3. Review enabled status, frequency, repetition, and start/end dates.
  4. If emailing, verify Bcc and course-specific message.
  5. Run a Practice Run, then review the “users identified” results link.
  6. If a formal Early Alert is needed, submit it separately.
